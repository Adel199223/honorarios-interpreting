# Completed fee-source history guard

## Goal and authorized scope

Prevent a later photograph of an already handled completed fee request from becoming another claim solely because photo capture defaults differ from its explicit performed-service date. This is a history-only guard: normal capture-day generation policy and work-scope review remain unchanged when no blocking history matches.

## Provenance and preserved contracts

The isolated candidate starts from the current saved public snapshot, including its existing uncommitted interface work. Exact touched-file beforeimages and hashes remain in ignored task evidence. The primary branch, private settings, sources, duplicate/draft/paper histories and existing artifacts are preserved. No provider, Gmail, publication or integration operation is part of implementation.

Derive exactly one foreground visible case and one affirmatively bound performed date from a completed fee demand. Reject ambiguous/background/model-only facts. Recompute from current source evidence rather than trusting posted derived fields. Never rewrite the intake date, infer police preparation, work scope, submission dates, Gmail evidence or payment receipt.

## Steps and acceptance

1. Add conservative parsing and an early positive-only history/exclusion/active-draft probe.
2. Enforce the same guard at preflight, preparation and signed prepared-artifact handoff/create/record boundaries.
3. Add fictional regressions for positive/negative evidence, manual conflicts, stale evidence and late history; run focused pinned tests.
4. Obtain independent review and normal browser acceptance, then apply exact reviewed touched files and validate the saved app within the authorized scope.

A separable Camera coverage correction reports the number of matching JPG/JPEG/PNG originals omitted by the existing 25 MiB limit, including searches with no selectable results. Limits, original bytes, decoding, freshness, prior source state and provider behavior remain unchanged.

## Risks and rollback

False source bindings are the main risk. Narrow foreground, clause, identity and date requirements plus no-match fallthrough keep this guard conservative. Explicit conflicting manual identities remain visible and cannot silently alter the source lookup. Rollback uses exact touched beforeimages; existing private state is never migrated.
