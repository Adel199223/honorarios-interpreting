| Source cases | `honorarios_app/source_cases.py`: source-grounded case references, ordered deduplication and ambiguity/administrative-reference checks; services review each child independently. |

| Verified source venue | `honorarios_app/source_location.py`: pure, uniquely matched GPS-plus-source venue proposals with current source/field provenance; private catalogs stay local. |
| Domain/CLI helpers | `scripts/`: authoritative PDF generation, classification, dates/questions, duplicate identity, recipient validation, packet preparation and local draft recording. |
| Explicit source exclusions | `scripts/request_exclusions.py`: shared runtime-local case/day/period guards and bounded ledger validation; no fabricated sent or paid status. |
| Runtime isolation | `honorarios_app/runtime.py`: separates config/data/output paths and initializes disposable synthetic fixtures for checks. |
| Optional providers | AI recovery, Google Photos and Gmail helpers: local configuration, secret-free status, guarded provider operations. |
| Durable local state | `gmail_attempts.py` reserves Gmail creation before the provider call; `scripts/state_store.py` supplies atomic JSON replacement and local process locks. Pending attempts remain recoverable from Recent Work after restart. |
| Future caller | `scripts/legalpdf_adapter_caller.py` and `/api/integration/adapter-contract`: versioned endpoint sequence and caller validation. |

## Workflow and safety

The normal sequence is source intake -> review -> numbered answers -> non-writing preflight -> PDF preparation and preview -> Manual Draft Handoff -> local recording of returned draft IDs. Missing Gmail OAuth does not block the manual handoff workflow.

Optional direct Gmail creation calls only `users.drafts.create` after current PDF/payload review, duplicate checks and acknowledgement. Draft verification calls only `users.drafts.get`. The user reviews and sends drafts manually; the app has no send, trash or delete operation.

The optional Recent Work sent-status check uses additional Gmail read permission. It performs bounded GET requests for active drafts and candidate Sent messages/attachments. Only an exact recipient, subject, complete attachment hash multiset and valid send time matched against unchanged reviewed local evidence can update a draft and every protected child to sent. Original IDs remain intact and separate sent IDs/evidence are retained. Missing, ambiguous, edited or legacy evidence stays protected for review. Automatic checks run on entering Recent Work with a cooldown; Sync now is explicit. Incremental authorization preserves the existing compose credentials on denial or partial consent. No OpenAI call is involved. See the [sent synchronization plan](docs/assistant/exec_plans/completed/2026-10-02_gmail_sent_sync.md).

Draft creation reserves each underlying case/date/period in an ignored local attempt journal before contacting Gmail. Lost responses block another create across concurrent requests, re-preparation and restart. Known returned IDs survive local-recording failures; recovery validates the original payload and attachment hashes and records locally without creating another draft. Uncertain attempts require explicit reconciliation. Original approved correction targets stay distinct from later conflicting history.

Manual handoff and local recording now recheck current history for every individual, packet, source-group and manual-visit child under the attempt/history locks. A request sent after preparation cannot be recorded back to drafted, and an active draft or pending attempt cannot be bypassed by the manual path. Same-ID retries require the same immutable evidence and cannot revive sent or retired history. Intentional corrections and known-ID interrupted-recording recovery retain their existing guarded paths.

Local backups now include the attempt journal and bounded recovery files for pending attempts. Restore merges newer local history and reservations, rejects conflicting identities/status/coverage, and preserves pending protection when reading legacy backups without the journal. Complete recovery files are rehomed under `output/email-drafts/restored-attempts`; original PDF bytes are retained while JSON paths/hashes are updated. Old prepared-review tokens/fingerprints are removed. Missing, changed, out-of-root or oversized files produce warnings and retain the blocker instead of making a retry safe. Recovery files are limited to app-owned reviewed JSON and supported PDF/images, 25 MiB per file, 100 MiB total and 256 entries. Credentials, completed-document archives, unrelated source files and browser sessions are excluded. Restore creates a pre-restore backup, reserves blockers before restoring artifacts/history, and supports interrupted same-backup retries with atomic per-file writes; it is not a transactional rollback of all local data.

Recognized undated historical translation receipts can round-trip through export, preview and restore using their source-message/case identity. Distinct receipts stay distinct, repeated imports stay idempotent and conflicting evidence stops restoration. This narrow compatibility path does not relax service-date or identity requirements for interpreting history. Confirmed paper-submission metadata is preserved by backups.

Prepared files use distinct versioned names. Personal-profile saves replace complete files atomically; an unreadable existing profile store stops instead of silently falling back and discarding secondary profiles. Selected IVA/IRS text controls the PDF. Capture-date extraction reads the original nested EXIF metadata and does not mistake modification time for capture time. Source references with fragmented suffixes remain unresolved. Exact destination matches take precedence over broader names, and deliberate field clears survive profile defaults.

Visible payer and venue replacements use the existing review-field reconciliation markers, including for non-photo inputs. A venue edit updates its dependent entity/type and PDF location phrase; an explicit PJ context retains the agency while the physical host changes. Untouched custom wording stays unchanged. A cleared ordinary venue receives a neutral building/city question; PJ-specific wording requires PJ context. Payer edits clear the previous addressee, contact aliases and an unchanged old recipient before re-review. The normal default addressee uses Juiz de Direito for courts and Procurador da República for Ministério Público; an explicitly supplied title is retained. A newly entered recipient remains subject to the normal payer validation, and a cleared recipient cannot be restored by an automatic service profile. These per-request edits invalidate prepared artifacts and do not change saved court preferences or travel choices.

When travel is selected, a physical-venue answer can fill missing destination and distance from the selected personal profile. Exact saved destination matches take priority; an institutional venue naming one unambiguous saved city can use that city's distance even with a separate unit suffix. Competing cities or an unrelated city mentioned only in a description do not supply a distance. Explicit destination/kilometers, including zero, remain authoritative, and the interpreting/travel choice is unchanged.

Current sent-duplicate reviews open an accessible decision dialog with a default No/stop action. Escape has the same result; Yes opens blocked review details only. The decision is bound to the current review, case/date/period, source and selected child, and clears on stale changes. It never authorizes generation or mutates the source siblings, queue or histories. Legacy missing-status records retain sent semantics. Source-group replacement controls require drafted blockers and remain unavailable for sent groups.

A validated sent duplicate uses a separate read-only summary of its returned history record, never the blank or conflicting current form. Unknown historical fields are omitted rather than requested. Current claim choices and generic missing-field/profile prompts are hidden for that match; every fresh sent child also produces an all-sent source summary without travel/replacement prompts. Mixed or stale source groups retain their normal review controls. The intake and durable history remain unchanged.

Manual entry stays disabled until service profiles are loaded and while the connection or runtime is unavailable. The same readiness guard runs before clearing any selected source or prepared work; a blank form uses the loaded default profile and proceeds to normal numbered questions. Reusable profile display filenames do not become source evidence during manual initialization or automatic profile merging; explicitly supplied filenames and actual upload provenance remain intact.

The local HTTP boundary accepts loopback Hosts and same-origin browser writes. Ordinary no-Origin CLI callers and existing OAuth GET callbacks remain supported; this is a local app, not an authenticated remotely hosted service.
